# Safety

This app simulates a gateway deciding on agent tool calls. It is built so that running it cannot reach anything real, and so that the decisions it shows cannot be faked from outside. Each rule below names the test that enforces it. Run them all with `npm test`.

| Rule | Enforced by |
| --- | --- |
| Everything is in-process or on loopback: the gateway is a stub, the agents are scripts, the tool servers are three stubs on `127.0.0.1:5851-5853`. The page has a Mock/Live toggle, but Live is refused (`GET /api/info`): there is no live gateway and no tenant. | `server/test/safety.test.js`: "default mode: every scenario, a human approval, an audit verify and a reset make zero non-loopback connections" (every non-loopback socket, DNS lookup and `fetch` is replaced by one that records and throws, for the whole run), "the guard itself works". |
| The gateway forwards only to `127.0.0.1` on a running stub port inside 5850-5899. The server's own port, a foreign port, another host and an empty allow-set are all refused before a socket opens. No request field carries a URL or host. | `safety.test.js`: "upstream target guard"; `guards.test.js`: "no route accepts a URL or host to forward to", "no body field can carry a credential or a target". |
| Source scan: no child process, `eval`, `fetch` or non-HTTP network module anywhere in `server/src`; only `upstreams.js` (and the server in `app.js`) touch HTTP; only `GATEWAY_INSPECTOR_*` environment settings are read. | `safety.test.js`: "source scan". |
| A denied, blocked or still-paused call never reaches an upstream. | `scenarios.test.js`: "benign reaches the upstream; denied and expired calls never do"; `safety.test.js`: "a denied or paused call opens no upstream connection at all". |
| Deny by default: an unknown agent, an unknown tool, bad arguments and any call no rule allows are denied. | `policy.test.js`: "deny by default", "non-object arguments are refused"; `gateway.test.js`: "deny by default: unknown agent, unknown tool, odd input shapes". |
| An agent cannot call a tool whose scope the registry did not grant it, whatever the arguments or rules. | `policy.test.js`: "scope". |
| Argument patterns: amount thresholds, directory containment (`..`, NUL, relative paths and `/data/publicity` do not match `/data/public/`), and prompt-injection text (folded with NFKC, hidden characters stripped). The scan reads every string value at any depth and every object key; if the arguments are too large to scan completely (more than 5000 nodes, or one string over 2000 characters) the call is denied as `prompt_injection` instead of being let through. Deny beats pause beats allow. | `policy.test.js`. |
| The policy tables are frozen and no route edits them. | `policy.test.js`: "the policy tables are frozen". |
| Pause / resume cannot be forged. A pause is released only by the one-shot code, which is random (128 bits), never in the agent's response, never in the call list, never in the audit trail, compared in constant time, consumed by the first correct use, void after expiry and after reset, and locked after three wrong tries. Two simultaneous approvals forward once. | `gateway.test.js`: "pause: holds the call ...", "approve ...", "two simultaneous approvals", "forging", "three wrong codes lock", "expiry ...", "the approval code never reaches the audit trail", "reset ..."; `api.test.js`: "human in the loop over HTTP", "expiry over HTTP". |
| Pause / resume cannot be forged cross-origin. A state-changing request (anything but GET/HEAD/OPTIONS) is refused with 403 when `Sec-Fetch-Site` is `cross-site` or when `Origin` is present and is not an `http` loopback origin identical to the `Host` it was sent to; a request with a body must be `application/json` (415). A page on another site can therefore not run a scenario, reset, or approve or deny a paused call, even if it knew the code. | `guards.test.js`: "CSRF: a cross-origin page cannot run a scenario, reset, or answer a paused call", "CSRF: ... text/plain". |
| The audit trail is append-only and cannot be mutated through the API. The only audit routes are two GETs; POST, PUT, PATCH and DELETE on them (and on calls) are 404 or 405 and leave the trail unchanged. In code the entries are frozen and handed out as copies. | `api.test.js`: "audit: read-only listing ...", "audit entries cannot be changed through the calls API either"; `audit.test.js`: "entries handed out are copies", "stored entries are frozen". |
| Tamper detection: editing, deleting, inserting, reordering or forging an entry makes `GET /api/audit/verify` report the first bad sequence number. A forger who recomputes the chain with a plain SHA-256 still fails, because the chain is an HMAC with a per-process key. | `audit.test.js`: "tamper detection ...", "a forger who recomputes the chain ...". |
| Queues are capped: 200 buffered calls, 20 pending pauses (past that a pause is denied), 2000 audit entries, scenario runs one at a time with one waiting (a third gets 429), rate-limit state kept only for the three registered agents, request bodies 2 KB, stored text and result sizes bounded. | `gateway.test.js`: "the pending queue is capped", "the decision buffer is a bounded ring", "rate limit state is only kept for registered agents"; `audit.test.js`: "the cap drops the oldest entry ..."; `scenarios.test.js`: "scenario queue"; `api.test.js`: "a third concurrent scenario run gets 429", payload 413. |
| Server and agent supplied strings (agent id, tool name, arguments, upstream answers) are redacted of secret-looking text and made inert (hidden and control characters shown as `[U+XXXX]`, sizes and depth bounded) before they are stored, returned or audited. Responses are JSON with `nosniff` and `Content-Security-Policy: default-src 'none'`. | `gateway.test.js`: "redaction and inert text", "hidden characters in an agent-supplied name"; `scenarios.test.js`: "a hostile upstream answer is shown inert and redacted (T-666)"; `sanitize.test.js`; `api.test.js`: "responses are JSON with nosniff". |
| No credential is accepted or used. A request with `Authorization`, `Proxy-Authorization` or `X-API-Key` is refused (400), on every route including health and the static UI files. The only body fields are `hold`, `decision` and `approvalCode`. The approval code is demo data inside a JSON body. | `guards.test.js`: "credentials are refused", "no body field can carry a credential or a target". |
| The server binds `127.0.0.1` only and refuses another address unless `GATEWAY_INSPECTOR_BIND` is set (the container does). A missing, malformed or non-loopback `Host` header gets 421. | `safety.test.js`: "binds loopback by default", "a started server is actually listening on loopback only"; `guards.test.js`: "Host guard". |
| A 500 never returns `err.message` or a stack; a bad URL encoding or call id is a 400. | `api.test.js`: "a 500 never leaks", "calls: list with polling cursor ...". |
| Every port is in 5850-5899. | `safety.test.js`: "ports"; `scripts/compose.test.mjs` for the published port. |
| The container publishes its port on loopback only, with no host mounts, no docker socket, no host network, a non-root user, a read-only root filesystem and no capabilities. | `scripts/compose.test.mjs`. |
| The UI is served by the server itself with a same-origin CSP (no inline script, no `unsafe-eval`, no off-origin source), behind the Host and Origin guards; dotfiles are not served; the API keeps `default-src 'none'`. The UI sends no credentials and shows every agent or upstream string as inert text. | `server/test/static.test.js`; `web/src/test/inert.test.jsx`, `web/src/test/app.test.jsx` (requests are same-origin, `credentials: omit`, the approval code is never rendered); `scripts/e2e.mjs` (no off-origin request, no console error). |
| No real credentials in the repo. | `.githooks/pre-commit` runs gitleaks on staged changes and refuses the commit if gitleaks is not installed. Test fixtures that look like tokens are assembled at run time. |

## Red checks

The key guards were mutated one at a time (the check removed or inverted) and the suite was run; each mutation made at least one test fail. The list and the result of the last run are in the README under "Verification". The release-claim mutants are listed there too and can be re-run with `node scripts/mutants.mjs`.

## What is not covered

- **The release claim itself.** The four scope layers, the hold outcome and single-use approvals are Ping's claims for a release dated 2026-11-02. This app shows a model of them. It does not show that the product does this, that the attended or unattended claim exists in a real token, or how a real approval is bound. Field names reused from the console swagger prove only that the names exist.
- **The token is a table.** There is no signature, issuer, audience or lifetime. "Verified token" means a lookup in a frozen table the lab owns.
- **One approver, one approval.** Distinct approvers, required approval counts, notifications, retirement and the Jira, ServiceNow and Slack hooks that appear in the swagger are not modelled.
- **No scenario for an evaluation error**, because nothing a scripted agent sends can make the evaluator fail; it is proven with an injected failing evaluator.

- **The approver is whoever can reach the page.** The approval code is shown to any same-origin client through `GET /api/calls/:id`, because in this demo the browser on the loopback origin is the human. In a real gateway the approver is a separate, authenticated channel. What this demo does guarantee is that a page on another origin cannot approve, and that an agent's own response never carries the code.
- **Cookie headers are not checked and never read.** Cookies are scoped by host, not port, so other local apps' cookies reach this server; it does not look at them, does not refuse them, and does not send any.
- **The audit chain proves integrity inside this process, not to a third party.** The HMAC key lives only in memory, so verification is a server-side answer; there is no external anchor. Someone who can change process memory can change the key and the trail. `POST /api/reset` discards the history on purpose (recording the head of what it discarded), and the trail is lost when the process exits.
- **Injection detection is a short list of English patterns plus hidden characters.** Paraphrases, other languages, encoded or split text are not detected. A clean result means nothing matched, not that an argument is safe. Strings are compared after NFKC folding; lookalike letters outside NFKC (for example Cyrillic) are not folded.
- **Path containment is lexical.** It normalises and rejects `..`; it does not resolve symlinks (there is no filesystem behind it).
- **The rate limit is per registered agent, in memory, with a sliding window.** There is no per-tool or global limit.
- Redaction is pattern based. A secret in a shape none of the patterns knows, in a field with an innocent name, is not removed.
- The stub upstreams answer fixed data. They prove the forward path, not the behaviour of any real tool.
